# Архитектура гибридного хранилища TechData Solutions

## 1. Executive Summary

Компания TechData Solutions хранит 500+ ТБ видеоконтента. Бизнес требует:
- Быстрый доступ к активным проектам (менее 100 мс).
- Экономичное хранение архивов.
- Автоматическое управление жизненным циклом данных.

Решение: трёхуровневое гибридное хранилище:
- HOT (SSD, локально) — активные проекты (10% данных).
- WARM (MinIO + s3fs) — недавние проекты (30%).
- COLD (S3-совместимый архив) — архивы (60%).

Данные автоматически мигрируют между уровнями по политикам, основанным на времени последнего доступа. При обращении к холодному файлу он автоматически продвигается (promote) на HOT.

---

## 2. Бизнес-требования

| Требование | Значение |
|---|---|
| Объём данных | 500+ ТБ |
| Активные проекты | 10%, latency < 10 мс, доступ 24/7 |
| Недавние проекты | 30%, latency < 100 мс, ежедневный доступ |
| Архивы | 60%, допустимо восстановление за часы |
| Бюджет | Минимизация стоимости при сохранении SLA |

---

## 3. Архитектура решения

### 3.1. Схема

Приложение (клиент) -> HybridStorageManager ->
  HOT (локальный SSD)
  WARM (MinIO bucket hybrid-warm через s3fs)
  COLD (MinIO bucket hybrid-cold, архив)

При обращении к файлу в WARM или COLD выполняется автоматический promote в HOT.

### 3.2. Компоненты

| Компонент | Технология | Назначение |
|---|---|---|
| HOT | Локальный SSD (hot_storage/) | Активные файлы, latency < 1 мс |
| WARM | MinIO bucket hybrid-warm через s3fs | Недавние проекты, около 50 мс |
| COLD | MinIO bucket hybrid-cold (архив) | Долгое хранение, секунды |
| Менеджер | Python-класс HybridStorageManager | Управление уровнями, миграция, promote |
| Метаданные | JSON (metadata.json) | tier, last_accessed, access_count, checksum |

### 3.3. Особенности реализации

- Все файлы при записи попадают в HOT. Это обеспечивает максимальную скорость для свежих данных.
- При чтении файла из WARM или COLD выполняется автоматический promote в HOT.
- Чанковое хранение не используется — для демонстрации достаточно целых файлов.

## 4. Политики миграции

| Переход | Триггер | Параметр |
|---|---|---|
| HOT -> WARM | Файл не читали N дней | N = 7 |
| WARM -> COLD | Файл не читали M дней | M = 30 |
| COLD -> HOT | Любое обращение к файлу | Автоматически |

Алгоритм migrate():
1. Проходим по всем метаданным.
2. Для каждого файла вычисляем age = now - last_accessed.
3. Если файл в HOT и age > 7 дней — переносим в WARM.
4. Если файл в WARM и age > 30 дней — переносим в COLD.

Алгоритм get():
1. Читаем файл из его текущего уровня.
2. Если уровень не HOT — удаляем из старого, записываем в HOT, обновляем tier.

## 6. План внедрения

| Этап | Длительность | Что делаем |
|---|---|---|
| 1. Пилот | 1 месяц | Развернуть MinIO + s3fs, мигрировать 1 ТБ тестовых данных |
| 2. Интеграция | 2 месяца | Подключить приложение к HybridStorageManager |
| 3. Миграция данных | 3 месяца | Постепенно перенести 500 ТБ, начать с архивов |
| 4. Мониторинг | постоянно | Настроить Grafana + Prometheus, алерты |
| 5. Оптимизация | постоянно | Тюнинг политик по факту использования |

Риски:
- Долгая миграция архивов — компенсируется параллельной загрузкой.
- Неверные политики — частые promote. Решается тюнингом N и M по метрикам.

---

## 7. Мониторинг

Метрики:
- Количество файлов по уровням (HOT/WARM/COLD).
- Средняя latency чтения и записи по уровням.
- Частота миграций (файлов в час).
- Частота promote (файлов в час).
- Использование дискового пространства по уровням.

Инструменты:
- Prometheus — сбор метрик из приложения.
- Grafana — визуализация дашбордов.
- Alertmanager — алерты.

Ключевые алерты:
- HOT > 90% использован — нужно расширить SSD.
- Promote rate > X/мин — политики слишком агрессивны.
- Migration failed — проблема с MinIO.

## 8. Заключение

Гибридная архитектура TechData Solutions:
- Обеспечивает latency менее 10 мс для активных проектов.
- Снижает стоимость хранения на 80% по сравнению с полностью SSD-решением.
- Автоматически управляет жизненным циклом данных.
- Готова к масштабированию до петабайт.

Реализация выполнена на open-source стеке (MinIO, s3fs, Python), что исключает лицензионные платежи и упрощает поддержку.
